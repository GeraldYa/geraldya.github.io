从零售店长到独立交付生产代码，我用了6个月

Gerald Yang 2026年4月 阅读约7分钟

2025年10月，我写不出一个函数。到了2026年4月，我已经有10个服务跑在生产环境，每天为真实用户提供服务。没上过训练营，没有计算机学位。靠的是十年对技术的好奇心，和一股不甘心只当旁观者的劲儿。

以下是一份诚实的复盘。

背景：并非从零开始

先说清楚：严格来说，我的起点不算零。我在科技零售行业干了 9年——卖过电脑、管理过 Apple 授权经销商、做过 Geek Squad 上门维修技术员。这些年下来，我对以下这些东西有直觉：

  • 系统的运作原理（网络、存储、操作系统）
  • 用户到底需要什么（跟上千个客户聊出来的经验）
  • 生意怎么转（损益表、库存、团队管理）
  • PowerShell 脚本自动化（我最早的"编程"经历）

但我完全没碰过的是：Web 应用开发、API 对接、JavaScript / Python / Node.js，以及怎么部署一个服务。

时间线

2025年10–11月

第一次接触 Claude AI。拿它当编程老师，每一行代码都要它解释清楚。写些小脚本——天气查询、文件批量重命名、价格爬虫。进度慢得让人绝望。

2025年12月 – 2026年1月

第一批真正的项目。发现了 OpenClaw（AI 辅助开发平台），同时直接用 Claude 构建项目。学会了 API Key、async/await、错误处理。做了 Polymarket 交易看板——真金白银押在上面，API 对接必须搞对。学了 Express、REST API、ethers.js。

2026年1–2月

Polymarket 看板日趋成熟。出版了书籍《Tokenomic: REPRICED by AI》。写书过程本身也是 AI 辅助完成的——又一个证明：这些工具放大的是已有知识，而非替代它。

2026年2–3月

ESP32 墨水屏项目。从 Web 跳到嵌入式（C语言、ESP-IDF），完全是另一个世界。做了一个服务端渲染器，把天气、股票、新闻推送到实体墨水屏上。同期搭建了媒体管理工具。从 OpenClaw 转向 Claude Code——速度质变。

2026年3–4月

多智能体 AI 平台。到这个阶段，感觉什么东西松动了。动手写代码之前，我先在纸上画了系统架构图：五个方框，箭头连起来，底下是共享文件系统。画了十分钟，画完才发现——我全程没查任何资料，架构已经在我脑子里了。自己写了 Telegram Bot，后来迁移到 Claude Code 官方 channels。基础设施成熟期：Cloudflare Tunnel、家用仪表盘、统一工具箱入口、监控。10个服务跑在生产环境。

真正管用的方法

1. 拿 AI 当老师，不当拐杖

我大量使用 Claude，但从不复制粘贴了事。我的规矩是：如果我解释不清每一行在干什么，就不上线。开头确实慢，但这意味着我是真学到了东西。

流程是这样的：描述需求 → 拿到代码 → 逐行读 → 追问"为什么用这个方案" → 自己改 → 改崩了 → 修好。

2. 只做真问题，不刷教程

我一个教程都没刷完过。每个项目的起点都是一个我自己遇到的实际问题：

  • "我想跟踪 Polymarket 的交易" → 交易看板
  • "我想要个智能家居屏" → 墨水屏项目
  • "我想要能记住我的 AI 助手" → 多智能体平台
  • "我需要快速给客户出报价" → ServiceQuote 工具

事实证明，修自己用坏的东西带来的动力，是做别人练习题的十倍。

3. 先上线，再迭代

我第一个 Telegram Bot 只有50行代码，没有错误处理，三天两头崩。但它够用，能验证想法，后面的势头就接上了。到现在，每个项目至少重写过两遍。

4. 零售经验比你想的更有用

哪些技能迁移过来了，说出来我自己都意外。九年里给各种困惑的家长解释内存升级，练出来的表达能力，写 UI 文案时直接就用上了。给客户排查一台坏掉的 MacBook 和排查一个崩溃的 Node.js 进程，用的是同一套逻辑：隔离问题、复现、测试。

管过门店——真实的损益、真实的库存、真实的排班——让我养成了一个习惯：先问"这个跑起来花多少钱"，再问"这个能干什么"。这个问题省下的工程时间，比任何框架都多。

两件重要的事

没人给我颁过"开发者"的头衔。我上线了10个服务，然后这就成了事实。

我所有东西都是在 AI 辅助下写的。我也能脱离 AI 解释每一行代码。这两件事不矛盾。

现在的我

六个月前我还在修打印机。现在凌晨两点我在跟我的 AI agent 争论代码架构。下一个六个月会怎样我不知道，但方法已经定了：找到问题，动手做，上线，改进。就这么简单，没有什么秘诀。
