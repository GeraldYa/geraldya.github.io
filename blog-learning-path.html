From Retail Manager to Shipping Production Code in 12 Months

Gerald Yang April 2026 7 min read

In January 2024, I couldn't write a function. By December, I had 7+ web services running in production, serving real users daily. No bootcamp. No CS degree. Just a decade of tech curiosity and a refusal to stay on the sideline.

Here's the honest version of how it happened.

Background: Not Starting from Zero

I want to be upfront: I didn't learn to code from absolute zero in any meaningful sense. I had 9 years in the tech industry — selling computers, managing an Apple reseller, diagnosing hardware as a Geek Squad field agent. I understood:

  • How systems work conceptually (networking, storage, operating systems)
  • What users actually need (thousands of real conversations)
  • How businesses operate (P&L, inventory, team management)
  • PowerShell scripting for work automation (my first "programming")

What I didn't have: any experience building web applications, any understanding of APIs, any knowledge of JavaScript/Python/Node.js, or any idea how to deploy a service.

The Timeline

Jan – Feb 2024

Started with Claude as a coding tutor. Asked it to explain every line. Built tiny scripts — a weather fetcher, a file renamer, a price scraper. Felt impossibly slow.

Mar – Apr 2024

First real project: a Telegram bot that answered questions using Claude's API. Learned about API keys, async/await, error handling. First time something I built was running on a server.

May – Jun 2024

Built the Polymarket trading dashboard. This was the forcing function — I had real money at stake, so I had to get the API integration right. Learned Express, REST APIs, ethers.js.

Jul – Aug 2024

ESP32 e-ink display project. Jumped from web to embedded (C, ESP-IDF). Completely different world. Built a server-side renderer that pushes weather/stocks/news to a physical e-ink screen.

Sep – Oct 2024

Multi-agent AI platform. This is where everything clicked. I understood enough to architect a system, not just glue APIs together. Docker, tmux, persistent memory, autonomous scheduling.

Nov – Dec 2024

Infrastructure maturity. Cloudflare Tunnel, home dashboard, unified toolbox portal, monitoring. Shifted from "building things" to "maintaining production systems."

What Actually Worked

1. AI as a Tutor, Not a Crutch

I used Claude extensively, but I never copy-pasted without understanding. My rule: if I can't explain what every line does, I don't ship it. This was slower at first, but it meant I actually learned.

The pattern: describe what I want → get code → read every line → ask "why this instead of that?" → modify it → break it → fix it.

2. Real Problems Over Tutorials

I never completed a tutorial or online course. Every project started with a problem I actually had:

  • "I want to track my Polymarket trades" → Trading dashboard
  • "I want a smart home display" → E-ink project
  • "I want AI assistants that remember me" → Multi-agent platform
  • "I need quick quotes for clients" → ServiceQuote tool
The motivation to solve your own problems is 10x stronger than the motivation to complete someone else's exercise.

3. Ship Early, Iterate Always

My first Telegram bot was 50 lines of code with no error handling. It crashed constantly. But it worked well enough to prove the concept, and that momentum carried me forward. I've rewritten every project at least twice.

4. Retail Skills Transfer More Than You'd Think

This surprised me most. My retail management background directly translated:

  • Customer empathy → I build UIs that non-technical people can actually use
  • P&L thinking → I consider hosting costs, API costs, and ROI before building
  • Troubleshooting instinct → Debugging hardware for years trains systematic thinking
  • Communication → I can explain technical decisions to stakeholders in plain language

What I'd Tell Someone Starting Today

Honest Advice

  • You don't need permission. No degree, no bootcamp certificate, no hiring manager's approval. If you can ship something that works, you're a developer.
  • Pick a language and stick with it. I chose JavaScript/Node.js because it runs everywhere (frontend, backend, scripts). Don't language-hop.
  • Deploy from day one. A project running on a server is infinitely more convincing than code on your laptop. Learn Docker early.
  • Build for yourself first. Your own problems are the best curriculum. You'll push through the hard parts because you actually want the result.
  • AI accelerates learning, it doesn't replace it. Use AI tools to explain, not just to generate. The developers who will thrive are the ones who understand what they're shipping.

Where I Am Now

I'm a Geek Squad field agent by day and a full-stack developer by every other hour. My production system runs 24/7: five AI agents, a trading dashboard, a media management suite, an IoT display, and a unified web portal — all on a NAS in my house.

I'm looking for a role where I can combine technical building with the communication and business skills I've developed over the past decade. If your team needs someone who ships fast and explains clearly, let's talk.
